# Changelog

## 0.8.4 (2026-11-10)

rb says on every interface how the checkout holds the record, opens those words one step down to what git said and how to check it yourself, and says in Reproduce whether your checkout has the code the runs ran.

- **One phrase for how the checkout holds the record.** rb says it in the same words everywhere: "all record files committed", "2 record files not committed", "12 record files ignored by git", "no commit yet", "not in git", "git not found" or "rb could not read git". The first that holds wins, in that order: not in git, git not found, rb could not read git, ignored, no commit yet, not committed. A note counts as 2 record files (its file and the log), a rename counts once, and deletions count. The record files rb keeps out of git itself (its cache, journal and lock) never count.
  - **rb open:** the Where button carries the phrase after the place's name ("Where main · 2 record files not committed"), at every place and in every state; the branch name gives way first on a narrow bar, and the phrase is never cut. The Where list opens on the place shown, with what rb found there (below), then each other place with its own line and counts. The place line under the bar is gone, and the Overview header no longer names the place. Esc closes an open list in the bar first, and `w` opens and closes Where. A past version is named by its UTC day on the Version button, the scope bar and the tab's title, and by its UTC minute where another version in the list has the same day.
  - **rb status** says the phrase on a line under the title, with "no branch · " before it on a detached HEAD. **rb context** says it as the first bullet of "The repository", with the commit and whether there are changes outside the record not committed. Where the commit does not hold the record, the bullet under it says so ("… since commit 247c1fbe53ed, which does not hold the record."), and `data.repository.line` reads "… at commit 247c1fbe53ed, which does not hold the record, with changes outside the record not committed".
  - **Pages** (rb page, rb export, rb sync's page, rb open's /page.html): About gains a second line, "2 record files not committed · at commit 9fa4f89a1b2c", stated from the checkout the page was made from, never from a bundle's copy. It never names a branch or a path. On the hub, the record's owner also sees the phrase at the end of the Overview's header line; a reader, and a page opened from disk, do not. rb page, rb export and rb sync end with "The page says: …" (`data.page_says`).
  - **rb ui:** the line under the head reads "main · 2 record files not committed"; `w` shows the highlighted place's path and what rb found there (below); the OBSERVED panel is titled "OBSERVED · UTC".
  - **rb doctor** names record files ignored by git (with the rule), git not found where a `.git` is there, and rb could not read git (with git's first line), each as a problem.
- **What rb found, one step down.** Where rb says how this checkout holds the record (rb status, rb context, rb open's Where list, rb ui's WHERE and a page's About), the words now open one step down to what rb found, in the same sentences everywhere. That is when rb checked, and what git said, with the counts and the commit ("rb checked the record with git at 2026-11-09 09:41 UTC: 2 of its 23 record files are new, changed or deleted since commit 9fa4f89a1b2c."). It names which files. On your own screens, wherever there is a repository and a git to ask, it adds a git command that only reads, to check it yourself from any folder.
  - **rb open:** the Where list gives that evidence for the place shown, with Copy for the whole commit and for the command. Its "just now" grows older once rb open stops answering. From 960 px to 1279 px the open list floats over the page, as it does from 1280.
  - **rb ui:** a click on the line under the head opens WHERE, as `w` does. WHERE prints the evidence under the places, with the commit whole and the command each on a line of their own, and the box scrolls.
  - **rb status** prints the evidence after its scope line. **rb context** nests it under the first bullet of "The repository".
  - **Pages:** in About, and in the Overview header the record's owner sees on the hub, the phrase links to a block in About. The block says what rb found when the page was made, gives the commit whole, names the files and says what record files are. A page published with its code's address (rb export --with-record --url, rb sync --with-record) adds more where that commit holds the record and git ignores none of its files: on any host, the lines that install rb, clone the code and check out that commit, and on github.com, gitlab.com or codeberg.org a link to the record's files at that commit. Where no branch git had fetched from that address holds the commit, or git had fetched no branch from it, the block says so in place of the link and those lines. No page carries the git command that only reads, a branch, or where the checkout sits on disk.
- **No branch.** A detached HEAD is "no branch" wherever a place is named, in place of "detached at <commit>", and a single checkout on no branch is named "no branch" rather than by its folder. A place keeps its folder's name only outside git, with git not found, or when git cannot be read.
- **Your checkout.** On rb open (its own Reproduce, and a run card's "Reproduce this run", which now draws the run's own code step) and in `rb show <experiment>` and `rb show <run>`, each code step says "your checkout has this code", "your checkout differs in 2 files: eval.py and quant/calibrate.py" or "rb could not compare your checkout", directly under the line that names the code it was compared with. Where it differs, rb open's "Show code diff" and rb show <experiment>'s "show code diff:" give the `git diff` to copy. It compares only files that code held, and leaves out the record and the files the runs name. It is never on a page or the hub, and rb status never compares code.
- **JSON.** `data.repository` (rb status, rb context, MCP, the SDK) gains `state`, `said`, `line`, `on_branch`, `record_files_not_committed`, `record_files_ignored`, `ignored_by`, `record_held`, `changes_outside_record` and `why`. It also gains the evidence: `record_files`, `not_committed_files` (each with its path, its change and, for a rename, where it came from), `ignored_files`, `checked_at`, `check` and `evidence`.
  - Two values change. `data.repository.branch` (rb status, rb context, rb reconcile) is null on a detached HEAD, where 0.8.3 said "HEAD", and names the branch in a repository with no commit yet, where 0.8.3 said null. `uncommitted` (rb status's Elsewhere, rb open's places and rb remove) counts record files as the phrase does, a deletion among them: rb remove counts a record file removed with `git rm`, where 0.8.3 gave 0.
  - rb show's code row gains `checkout`, and the shell's document is rb-shell-view/1.16. Every other change adds keys.
- **Retired words.** "tree dirty", "tree clean", "with uncommitted changes", "uncommitted changes kept as git trees", "The tree had uncommitted changes" and "This checkout changes the code at …" give way to "changes outside the record not committed" (the receipt's own rule, the same in every place). For what an export leaves out, they give way to "Not committed, so a rerun does not get it: configs/sweep.yaml." The export's Rerun panel says "The code when this page was made: <address> at commit <12>". Where a run's own config says its code had uncommitted changes, a finding says it as the config's: "a run it counts has a config that says the code had uncommitted changes when it ran".
- **Commits at 12 characters.** Every commit rb prints in prose has 12 characters, and every command it prints carries all 40 (rb show's `git diff` and `git checkout`, and the clone lines on a page). One exception: wherever rb names a source by its short form (an experiment's design listing, rb spec set and rb spec verify among them), the commit after its "@" keeps 7 characters, since confirmations made by earlier versions kept that wording.
- **rb journal's text** lists a git line only for a move of HEAD ("new commit", "3 new commits", "another commit checked out", then " · at commit <12>"); a change of the working tree's state or of the branch alone writes no line. Every line's time reads "09:40 UTC", and a command's line reads "(exit 0)" with no seconds. `--json` keeps every entry as before, with its flag and its seconds; each git entry gains `said`. rb ui's OBSERVED panel and Activity use the same words. The last `rb reconcile --apply` on rb status and rb context says its minute in UTC.
- **rb open from 960 to 1279 px** puts the working view beside the navigator. In 0.8.1 to 0.8.3 it sat in the navigator's narrow column and the second column stayed empty.
- **0.8.3's laters.**
  - `rb criterion relate --remove` beside an analysis's file that does not read names the file, as a declaration has since 0.8.3.
  - In an agent session, a read beside a note's file that does not read (`rb journal`, `rb log`) tells what it would tell on a clean record, and that the note's file changed outside rb; 0.8.3 told nothing. A read that stops at that file fails and tells nothing, as before. The manual says the two rules in two sentences.
  - The page's list of design cells for a count or a best of N says each cell's number is its mean, and what the rule reads instead ("the rule reads each cell's best unit"). The digits are those of rb show and the figure, as before.
- **A team on two versions.** rb 0.7.0, 0.7.1, 0.8.0, 0.8.1, 0.8.2 and 0.8.3 read the files 0.8.4 writes as they read their own: nothing new is stored. 0.7.0 and 0.7.1 refuse a record that holds a format-2 file and leave it unchanged, as before.

## 0.8.2 (2026-11-08)

## 0.8.1 (2026-11-07)

The page has one navigator at every width and says a rule's numbers in its card's digits wherever it shows them, and rb names a file raised to `rb: 2` by hand as no valid record.

- **One navigator at every width.** From 1280 px the page keeps its three panes. From 960 to 1279 px it shows the questions column and the working view, and a card opens as a sheet over the work. Under 960 px, and with no script, it is one row: Overview · Research · Experiments · Record · Your call (a reader's row holds the four places). The record's views start with their own row, Research links its Rules, and the bar names a question or an experiment by its title. The hub's one copy of the script lays out pages an older rb wrote as they were.
- **A file raised to `rb: 2` by hand.** A record file whose first line says `rb: 2` and that holds none of the four format-2 rules is no valid record (`E_STATE_CORRUPT`), where rb 0.8.0 said nothing. `rb doctor` names it and says to set its first line back to `rb: 1` (or `rb doctor --restore` puts back what rb wrote), every gate fails closed, and rb writes nothing over it until it is fixed.
- **A write beside a file that does not read.** A write beside a record file that does not read is made whole or not at all: it never leaves its own file written without its log line, as rb 0.8.0 could.
- **A file a newer rb wrote.** `rb show` of a file in a format newer than this rb reads says a newer rb wrote it (`E_STATE_NEWER`), as `rb status`, `rb doctor` and every write do.
- **The page says a rule's numbers as its card does.**
  - A comparison grid's cell that is a rule's reading says that rule's card's numbers, its estimate as well as its interval: a cited difference of means no longer reads 0.02967 in the grid beside 0.02968 on its card.
  - A relative rule's figure across design cells says its amounts in percent and in its card's digits.
  - A difference of means' or a relative change's card says each bound as `rb show`'s line writes it, with no 0 added ("-22.6 to -22.37").
  - A cited difference of means is said as one where its rule is shown: in the rule's row ("as a difference of means = 0.0317 ± 0.00005 nats") and in a design's "criterion added" line, which says a relative rule's threshold in percent, never in the metric's unit.
- **`rb compare`** names a criterion that reads a cell otherwise (a relative change beside a cited difference of means) beside the change it shows: `(also read by c1)`, and `read_beside` in `--json`.
- **Help.** `rb run add --every-row`'s help names a SQLite table too.
- **A team on two versions.** rb 0.8.0 reads every file 0.8.1 writes. The one file they read apart is a file raised to `rb: 2` by hand with none of the four rules, which 0.8.0 reads as fine and 0.8.1 names as no valid record.

## 0.8.0 (2026-11-07)

Four new kinds of rule (a count, a best of N, a relative change and a cited difference of means) are kept in record format 2, each is read its own way wherever rb reads it, and rb writes every other file in format 1, as rb 0.7 writes it.

- **Record format 2.** rb writes a criterion's file in format 2 (`rb: 2`) only while it holds one of four new kinds of rule (below), and writes every other file in format 1 (`rb: 1`), as rb 0.7 writes it. rb reads both formats.
  - A file that says `rb: 1` and holds one of the four is refused (`E_STATE_CORRUPT`: "is format 1 and holds over: count, which only format 2 has"), and `rb show` of such a file says it is not valid ("format 1 holds no over: count: only format 2 does, and rb writes such a file as rb: 2"). A format above 2 asks for an upgrade ("this rb reads formats 1 to 2").
  - A retracted rule keeps the rule it was, so its file stays in format 2. rb says nothing about a file raised to `rb: 2` by hand that holds none of the four, and its next write of that file puts back `rb: 1`.
  - `rb export --with-record` writes `record_format: 2` in the bundle's manifest when a criterion's file is in format 2, else 1 (every earlier rb wrote 1); the bundle stays `rb-bundle` version 2. `rb clone` keeps each of the four whole, in format 2, and refuses a bundle whose `record_format` is above 2.
- **Four new kinds of rule.** `rb criterion add` takes four new kinds of rule that format 1 cannot hold, each kept in its criterion's own file in format 2. Each reads a threshold its own way (`--at-most` or `--at-least`, or, for all but a best of N, `--equals` with `--tolerance`), and each is said in the same words by `rb criterion add`, `rb show`, `rb status`, `rb context`, the SDK and MCP.
  - **A count.** `--count K` reads whether at least K units meet the threshold, judging each unit as `--each` does, and `--of N` says how many units the rule is of: `--metric int8.val_loss --at-most 0.890 --count 4 --of 5` declares "4 of 5 units' int8.val_loss ≤ 0.89". Its reading names both numbers: "recorded values meet criterion: 4 of 5 seeds at most 0.89; the rule asks for 4". Where the runs hold another number of units than the rule is of, or fewer than K, it reads undetermined and says so: "criterion undetermined: the rule is of 5 seeds; the runs hold 4".
  - **A best of N.** `--best`, with `--at-most` or `--at-least`, reads the unit best in the threshold's direction against it, and `--of N` says how many units the rule is of, as for a count: "the best of 5 units' val_loss ≤ 0.889" reads "recorded values meet criterion: best of 5 seeds, seed 3: 0.8887 ≤ 0.889". Its reading is that unit's own value, never a mean: "a best of N is one unit's own value, with no interval".
  - **A relative change.** `--relative`, on a comparison of two arms, reads the relative change of the arms' means, (subject - reference) / reference, in percent, and its threshold is a percent: `--metric change.val_bpb --at-most -22.5 --relative` declares "change.val_bpb as a relative change ≤ -22.5%". The arms are paired where every unit holds both, and read apart otherwise. From 3 units its interval is a delta-method t interval ("relative change of the means, paired, delta-method t interval" on `rb show`'s reads line, `comparison.method` in `--json`); with fewer it has none, and a met rule reads "estimate meets criterion".
  - **A cited difference of means.** `--means`, beside `--source` and `--quote`, reads the cited number as a difference of the arms' means over all their units, with a Welch interval from 3 units in each arm. For "change.val_loss as a difference of means = 0.0317 ± 0.00005", `rb show`'s reads line says "difference of means, as cited" ("difference of means, as cited, Welch interval" once each arm holds 3 units). rb sets the cited number against that difference of means, never against its paired reading, so a unit that only one arm ran does not make the rule read "not comparable", as it can a cited rule without `--means`.
  - A relative change and a difference of means read a threshold on their estimate, or with `--bound` on their interval's bound ("change.val_loss as a relative change, upper bound ≤ 20%"). With `--each`, `--count`, `--best` or an interval rule they are refused ("a 'relative' reading takes a threshold on its estimate or its bound"), and so is an `--estimand` ("a relative or means reading is rb's own reading of the runs; it takes no estimand").
  - A met count or best of N reads "recorded values meet criterion" (a cited one, "reproduced on the recorded values"), since the recorded units themselves meet it, whatever the interval of the units' mean, and the tally counts it among the rules met on the estimate alone: "Rules: 1 met, on the estimate alone". Timing, calls and `--fail-on` gates read the four as any rule.
  - Their refusals include these, each naming its flags: "--of says how many units a count or a best of N is of", "a best run is best in a threshold's direction: --at-most or --at-least", "a 'relative' reading compares two arms: give a reference (or read change.<metric>)", "a difference of means is what a cited number measures: give its --source and --quote" and "--relative and --means each say what the reading measures." A count above its `--of` is refused ("a count rule's count is at most the units it is of"), and an interval rule takes none of `--each`, `--bound`, `--count` and `--best` ("a 'better' rule already reads the interval; --each, --bound, --count and --best are for thresholds").
- **The four, wherever rb reads them.** Each of the four is read its own way wherever rb reads it.
  - At one fixed design cell that `--where` selects, a relative change and a difference of means are read on that cell's runs, with its interval: "change.val_loss [where batch=32]: +0.5625 [+0.545, +0.58] % · relative change of the means, paired, delta-method t interval, 3 units, 95% (rb)".
  - Across fixed design cells, a relative change and a difference of means read each cell as their rule reads it and say the cells' range and how many meet in the rule's own unit ("descriptive range +0.1% to +0.5625%; no sampling interval across fixed cells · 1 of 2 cells meet the threshold"), and the rule reads undetermined: "a relative change is not read across fixed design cells, which are not independent samples; select one cell (--where) to read its replications". A count and a best of N judge every unit within the cells, as `--each` does.
  - Where a reading that pools a per-run setting meets its rule, a best of N, a relative change and a difference of means name each value whose runs alone would not meet it, read there as the rule reads them. A count names no value, since its K is of every unit it reads.
  - A count and a best of N read the runs a rule's `--where` selects, and an analysis of the comparison is said beside any of the four, never read in its place.
  - A relative change and a difference of means read each arm's own numbers, so where a run gives only the difference (`change.<metric>`), they have no reading.
  - A cited count or best of N is never set against the arms' means, so it never reads "not comparable" for that reason.
- **One way to read a threshold.** `rb criterion add` and MCP's `criterion_add` refuse two of `--each`, `--bound`, `--count` and `--best` together (`E_OBJECT_INVALID`: "A threshold is read one way: --each and --bound each say a different one.", with "Give one of --each, --bound, --count K or --best."), where rb 0.7.1 read `--each --bound` as `--each` and dropped `--bound` without a word.
- **The page.**
  - A count and a best of N say what they pass on ("At least 19 of the 20 units' values are at most 0.89 nats", "The best of the 20 units' values is at most 0.885 nats") and are said by their units ("INT8: 10 of 20 seeds at most 0.89; the rule asks for 19", "INT8: best of 5 seeds, seed 3: 0.8893 > 0.889"). The figure marks no design cell "outside the rule" for a count or a best of N, which judge units, not cells.
  - A relative change is said in percent, never in points, on its card, its verdict and a call's figure ("INT8 is 0.3914% lower than the FP32 baseline (-0.4438 to -0.339)"), and the runs under it keep their metric's own unit. A cited difference of means is said with ", a difference of means, as cited".
  - A sentence that starts with a metric's name keeps it as declared ("top1 is 0.74", never "Top1"), and headings, a run's card and the runs table name every metric as declared, never title-cased or split at a `.` (`acc` and `m.acc`, never "Acc" or "M acc"). A name that ends in its unit, such as `lat.ms`, is not followed by the unit again.

Revisions and withdrawals keep their history, frozen changes require an amendment, and clones inherit the structure without the parent's calls or evidence. Two branches that file one criterion to one question, or relate one pair, merge into a record that reads with neither declaration active (`question_link_ambiguous`, `relation_ambiguous`), and one filing or relation repairs it. rb's own next steps, items and guides link each criterion they offer to its question (`-q`), and once any criterion is linked or related, `rb status` gives the agent `unassigned_criterion` for each criterion filed under a question and linked to none, with the filing that links it. - **The agent contract.** `bench/agent/` is the executable definition of an rb-compatible agent: a spec of nine invariants (record the moment that mattered, skip the chatter, keep the user's words verbatim, never manufacture a finding, reconcile before finishing, notice a failed check, use the grammar, cite files, start honestly where the work already is) and nine cases, each a synthetic repository with rb installed the way a user installs it, a short session, and checks read from what the agent left in `.rb/` and what it said. `python bench/agent/run.py` plays them with scripted agents; `--agent-cmd` plays them with a real one, behind a counting `rb`. - **Findings are read on axes, never in one word.** A criterion is a rule over one comparison (subject, reference, metric, estimand) with a role (primary, secondary, exploratory, gate). Its finding says, computed on every read: the comparison with its interval and units; the result (gain, loss, unresolved, equivalent, point only, measured); whether the rule meets, misses, is undetermined or untested; the timing (declared before the evidence, after it, after the data was seen, or in an order nobody knows); how many independent units it rests on; every integrity problem with what it depends on; the latest decision on it and whether it was made on the reading as it stands; and the readings it replaced. The headline is `rule · result` (`criterion met · loss`, `gate missed · point only`). rb reads the runs itself: a paired difference per unit, averaged within units, then over units, with a Student t interval from 3 units (Welch when the arms never share a unit). Thresholds read the estimate (`--at-most`, `--at-least`, `--equals`; `--each` for every unit, `--bound` for the interval's bound); `--better`, `--noninferior M` and `--equivalent M` read the interval. A missed gate is a priority call, never a refutation.
- **Units, not rows.** Runs with the same per-run values are one unit; `population.unit` names the setting that defines units (2 photographs with 4 noise cases each are 2 units); `--repeats <run>` records a check of a run, averaged with it. `--min-n` counts units. A run's identity is its provenance: the same output files are one run; equal numbers from two executions are two runs.
- **Analyses.** `rb analysis add <exp> --compare "a/b:m@estimand=est[lo,hi]" --method --unit --units --reads --input --source` records a computation over saved outputs and the comparisons it produced, checked against the document that states them. An analysis that reports a comparison is read in place of the runs, and rb's own reading stays as history; a corrected one `--supersedes` the old with a reason, and every earlier reading stays on record. What an analysis rests on is traced every step back, and one that counts more units than the runs it read form (by the declared unit) is an integrity problem.
- **Timing and exposure.** A criterion is declared when it is written, by whoever wrote it. Its timing compares that with when its evidence existed (`--produced-at`, the journal, git, the file's time, or the record time, and it says which) and with when its evaluation data was seen (`rb resource expose`, or another experiment evaluating on the same resource). Evidence it could have been fitted to counts even after a spec change. `late` fails when a primary criterion is not shown to precede what it reads.
- **Decisions.** A decision (`rb decide <subject> accept|reject|investigate|continue|park|stop|pivot|ship --why --revisit`) records the reading of every finding it was made on; when a reading moves, or a new one appears under it, it says it was made on an earlier reading.
- **rb tracks who did what.** rb never refuses a write because of who makes it. Freezing, amending, deciding (accept, reject, investigate, continue, park, stop, pivot, ship), vouching for a setting, retracting anything and `rb doctor --adopt` work for anyone and are recorded as whoever made them; a call recorded in an agent session waits for the user's confirmation (above). Attribution is the integrity: every write records who made it (`human:<name>` or `agent:<name>`), the chat session when the runtime exports one (on every log.jsonl line, on decisions, on run receipts), and the reason as given (`--why`); inside a detected agent session `RB_ACTOR=human:<name>` is ignored, so the record shows who actually did what. When an agent acts on the user's words from the chat, it passes them verbatim with `--words "..."` (on every command that takes `-m`/`--why`, and on `question add`, `experiment add` and `note add`; `words` in MCP tools and in the SDK's `decide`, `retract` and `freeze`): they are kept beside the reason on decisions, freezes, amendments, retractions and criteria, and on the log line, and shown as `your words: "..."` once they are the user's (above). Nothing is paraphrased. `rb status` items carry `who` as a hint of who usually acts, not a permission: calls on results and on lines of work (undecided, gate missed, decision outdated, investigating) are the user's, setting items the agent's, and drift, changed cited sources and state from a newer rb anyone's; an agent records a call when the user asks for it, with their words.
- **Which agent made each write, and on which model.** An agent's write records `agent` on its log line and, for a run or an analysis, on its receipt: its name, its version (from `AI_AGENT` or the MCP client's `clientInfo.version`), its provider (as it said it, else inferred for Claude Code on Anthropic's own API, Codex and Gemini CLI) and its model, only as it said it: `rb context --model <id>` (or the context tool's `model`) for the rest of its session, or `RB_MODEL` for one command. With no session id rb keeps no model. A session's agent facts get one `session` line in the log, for each writer and channel in it, when they are first known or change; it records no write, and rb versions before it read past it. `rb_delta` says once how to give the model while none is recorded, `rb context` says it in every briefing until one is, and `--json` gives the actor with `agent`. Cursor's agent (`CURSOR_AGENT=1`, its chat in `CURSOR_CONVERSATION_ID`) and Codex known only by its thread or session id are recorded as agents. A human's write keeps a session only when `RB_SESSION` names one, so a Cursor terminal's trace id is no longer taken for a chat. An adoption can no longer change a receipt's actor, `actor_via`, `via`, session or `agent`, nor the `via` beside who wrote a record.
- **Who made a write is in the data, not in rb's words.** rb's text and every sentence it builds name no writer, a human or an agent, so a missing name never marks an agent's write: a call reads as made, when and why (`accepted 2026-10-10: within budget`), a criterion as declared before or after its evidence, a line of `rb log` as what changed. No session id, channel or detection source is in them either, and no branch or worktree is named as a write's: `rb status` names each place elsewhere by its branch and path, as rb names a place in the labels it computes for one; what a command printed in a worktree removed since is found as such, with no worktree's name. The record and the fields of `--json`, MCP and the SDK keep all of it; `rb doctor` still says how this shell's writes are recorded.
- **Publishing the record is a choice.** `rb export` and `rb sync` publish the page alone, with a manifest hashing it: no record, no file a check reads, no `bundle.zip` and no Reproduce panel with `rb clone`. `--with-record` (`with_record` in the SDK's `export` and the MCP `export` tool) carries the record too, as the bundle rb wrote before, and rb says then what the record keeps: who made each write, an agent's chat session, name, version, provider and model, the user's words passed with `--words`, and each run's host, platform and branch; the bundle's README says it too. `--url` takes `--with-record`, since there is nothing to clone without it; `rb clone` of a page alone says it was exported without the flag; `--json` says which was written (`with_record`).
- **No screen names a writer either.** The page `rb page`, `rb export` and `rb sync` write, `rb open` (with the `/state.json` and `/card.json` its tab draws, where each field that kept who wrote now holds `""`, whatever the record keeps there) and `rb ui` name no writer, session, channel, agent or branch, and use no word for a role: runs have no "recorded by" column, a relation's declarations print what has a value, "For your agent" is the Next step, and what is not the user's call is "still open in the record" (`open in the record · N` on `rb ui`, whose `a` key opens that list). `rb ui` counts what was written since the user last looked, whoever wrote it (`Since you last looked: 3 writes, 2 runs recorded · last <day>`), and nothing before their first look, and its `y` prompt says what a yes records, not as whom. The user's words show on `rb open` and `rb ui` without the `your words:` tag, and never on a page, which anyone may be sent; nor does a page show the platform a run's receipt keeps, which `rb open` shows. The screen refuses an agent session as `rb ui` does when it is started with `python -m rabbit_brain.tui` too.
- **Plain record text.** rb shows the text anyone writes exactly as written, on every screen, so the manual and the contract `rb compile` prints ask for plain text (a statement lifted from a report keeps its words and drops its markup): Unicode symbols (≥, ×, Δ, σ, ∼) instead of LaTeX, a macro's name spelled out, no citation keys or table and figure references, and no name of the agent or tool that did the work. After an agent's write whose new text holds LaTeX, rb says so in one line that names the field and what to write instead: after the write's text, among `data.warnings` in `--json` and over MCP, and as a `rabbit_brain.RBWarning` from the SDK, which now also warns of what `rb run add` and `rb analysis add` warn of beside a write (an input whose copy here changed, numbers typed with no document, numbers that differ from the run already recorded with the same output files). The user's words, quotes of files and commands as given are never flagged, nor is a price, a path, a shell or Make variable, a regex or a code span; a human's writes get none, and rb never refuses or changes the text.
- **A project is titled for the work's theme.** `rb init "<the work's theme>"` names what the work shares (a paper's title, a model, a line of work), and each inquiry is a top-level question with the experiments that answer it. rb init's help and the next steps it prints (`rb question add`, then `rb experiment add -q`), `rb status` on an empty record, `rb context`, `rb compile`, the `E_NO_PROJECT` fix, the tour, the skill and the docs say so.
- **Questions are a tree.** `rb question add --parent`, `rb question move`, and an experiment filed under several questions (`-q q1 -q q2`, `rb experiment file`); a question's state comes from the decisions on it, and its roll-up counts the findings linked to it by rule and by result, and the sub-questions and planned experiments below it.
- **Integrity is local and forged authority is none.** A record changed outside rb is an integrity problem of the findings that depend on it, and only those; the rest keep their readings. A decision rb did not write is nobody's call, and an adoption can never change who wrote or decided something (`E_ADOPT_AUTHORITY`); a run deleted outside rb is named by the findings it fed; `rb show` of an edited record says what changed.
- **The record is plain YAML in `.rb/`, one file per record.** `.rb/project.yaml` and `notes/`; `questions/<id>.yaml`; `experiments/<id>/experiment.yaml` with a file per variant, note and criterion under `variants/`, `notes/` and `criteria/`, per run under `runs/` and per analysis under `analyses/`; `metrics/`, `resources/`, `decisions/`; `log.jsonl`; and, local and gitignored, `cache/`. Every file opens with `rb: 1` and then its `kind`. The files keep to a strict subset of YAML, Rabbit Brain YAML (mappings, lists, strings, numbers, booleans, null, comments; no anchors, aliases, tags or merge keys; a value YAML 1.1 and 1.2 read differently must be quoted), read and written by rb's own parser, fuzzed against PyYAML. Comments survive rb's rewrites, and a comment or a reformat is not an edit: tamper detection compares each record's content hash. `rb fmt [--check]` writes the canonical form; `rb show <file>.yaml --json` gives canonical JSON and the hashes log.jsonl records.
- **One vocabulary, everywhere.** The record's words are project, question, experiment, variant, setting, criterion, run, analysis, comparison, result, resource, metric, finding, decision, note and relation: the same words in the files, the JSON Schema, the CLI, MCP, the SDK, the docs and every screen. A hypothesis is what an experiment tests, and a direction nothing has run yet is a planned experiment; an assumption is a note.
- **The format is a published contract.** `rb schema all` prints format 1 as one JSON Schema, committed as `schema/rb-v1.schema.json` (its `$id` is https://rabbitbrain.ai/schema/rb-v1.schema.json), with a test that fails when it drifts from what rb enforces.
- **Resources: identity, location and availability are separate.** `rb resource add <id> --type dataset --name "..." [--version --file --sha256 --digest --at PROVIDER:REF --url --recipe]` records what a dataset, checkpoint, code or artifact is and where its bytes have been (local, url, git, W&B, S3, GCS, Hugging Face, RunPod); `rb resource locate` adds a place. Availability is computed on every read: present, changed (a copy is here, not the bytes named), remote, reconstructible, lost. Identity is as exact as what was recorded, and says so: exact (a hash or digest), version, or name only. Deleting a 100 GB copy never loses what the benchmark was.
- **A run pins what it touched.** `rb run add --input RES[:ROLE] --output RES[:ROLE] --host provider=runpod` records, per resource, where it stood and the bytes of the copy here when the run was recorded; a copy whose bytes differ from the resource's identity is recorded as found, with a warning. Every experiment says what a rerun would need and where each piece stands (code, environment, machine, resources, files), and a dataset that changed after the runs read it is named as such.
- **Experiments carry their story.** Purpose, hypothesis and why; notes, verbatim with their writer; relations to other experiments, shown from both sides; a computed state (planned, open, or what the latest decision made it: accepted, rejected, investigating, parked, stopped, pivoted, shipped). Experiments, runs, analyses and resources carry global uids.
- **`rb status` answers where the record stands on its own**: the questions and their findings, then what needs a human and what an agent can do (each item saying who usually acts), what the experiments depend on, what ran (and whether every receipt is what rb wrote), and the project's notes. A long list in `rb status` or `rb context` names its first or latest ones and counts the rest, with the command that lists every one, so thousands of results folders or hundreds of runs keep the first screen readable; `--json` keeps every item. In the user's own terminal, the Next line names `rb confirm` first while a call waits on them. Its first line says the project's title once where the title is the project's id, and a count of two reads as both (`after both its runs were made`, `both units`), of one as the only one, never `all 2`. A test cuts the network and removes any account, then runs status, show, compare, context, log, doctor, env check, fmt, schema, page, export, reconcile and clone: none of them may need rabbitbrain.ai.
- **`rb open` only reads**: every POST gets 405, and there is no launch key. What rb found in the repository and nobody recorded shows as facts, not requests: under "Your call" in `rb ui` and `rb page`, under "Found in the repository" in `rb open`, beside how many calls wait on you, which `rb status` lists under Needs a human. The list of the calls waiting on you, on `rb open` and the page, names each one once, by what it asks and the title of what it is on, linked to the deepest question that lists it, so it holds as many as the count says.
- **Bundles are `rb-bundle` version 2** (the record inside is `.rb/`, format 1). A bundle's page is computed from the bundle itself, carries the documents its analyses were checked against, and `rb export --with-record` names the resources it leaves behind and says what the record it carries keeps, which anyone who can read the bundle can read. A clone keeps each setting's source (verification is redone here with `rb spec verify`), gives every experiment a new uid and a `reproduces` relation to the parent's, and keeps resources' identities while leaving another machine's paths behind. A bundle holds at most 512 MB, zipped or unpacked: `rb export` refuses one that would hold more, naming its largest parts, and `rb clone` one that does, and what `rb clone`, `rb export` and `rb sync` have half made is taken away when Ctrl-C, SIGTERM or SIGHUP stops them; a clone keeps its parent's address without the credentials, query or fragment it was fetched with, and a published fork's page links the parent only at a web address.
- **rb never publishes.** rb and rabbitbrain.ai are like git and a code host. `rb publish` fails with `E_NOT_AVAILABLE` and says what to use. `rb export` writes the page you can host anywhere, and with `--with-record` a bundle that `rb clone` reads; `rb login` and `rb sync` are an optional bridge to the site, where sync puts a private copy of the page (and of the record with `--with-record`) in the user's account and making it public happens on the site, from the record's page. The hosted service is not open yet: until it is, `rb login` and `rb sync` addressed to rabbitbrain.ai say so (`E_NOT_AVAILABLE`), send nothing, and name what works without it (`rb page`, `rb open`, `rb export --with-record`); a hub named with `--hub` or `RB_HUB_URL` is still called. `rb --help` groups the commands to match: "Calls" (freeze, decide, retract), "Carrying it" (export, clone, env), and "rabbitbrain.ai (not yet available)" (login, logout, sync) last.
- **Agents are told when to record.** The MCP server's instructions say to record when the research state materially changes (a question or hypothesis introduced, revised or dropped; an experiment or control proposed or run; evidence that changes a conclusion; a baseline, variant or metric established; an important uncertainty; the next experiment or a decision chosen) and not implementation chatter, to point at the repository's own files rather than copying their prose, and that `rb reconcile` finds results that landed unrecorded. The packaged skill (`rb skill`) says the same in about fifty lines and defers to `rb docs` for the rest.
- **Where rb looks, said where it reads.** `rb status`, `rb context`, `rb open`, `rb ui` and the page say where rb looks on its own (`out/`, `outputs/`, `results/`, `eval-out/`, `metrics/` and any folder a recorded run named, the files in the repository's top folder, and the .json, .yaml and .toml files git shows as new or changed), when it last looked, that it reads what code, configs, docs and database rows say only where the record points to them, and that it sees only the commands run through `rb journal run`; `rb reconcile` reads the same list. Where git's folder cannot be written (an agent's sandbox can keep it read-only while the project stays writable), the journal and the ownership ledger are kept beside the record in `.rb/` and that line says so; the first look that can write git's folder moves them there.
- **Changes nothing in the record cites.** A .json, .yaml or .toml file outside the results folders rb reads that changed since the record's start, or since the last `rb reconcile --apply` in the user's own name, and that no setting, run, analysis, criterion, call, resource or indexed folder cites, is listed by `rb reconcile` by path with the commit the count starts at, and counted in one line on `rb status`, `rb context` and the user's screens (`uncited_changes` in `--json`). rb says what changed and that nothing cites it, never whether it matters. `rb reconcile --apply` keeps their paths on its line, so they are recorded while their bytes are those.
- **Recovering what nobody recorded, honestly.** `rb reconcile` says where it looked, never proposes a file of progress numbers as a run, nor one that was there when `rb init` first looked (that is the work the record began after), moved or copied from it, or put back from git by a stash or a restore (a result rb saw land keeps that look through a stash or a checkout, and is still proposed), and the journal shows when a file was last written, not only when rb saw it. `rb compile` lists files matched by metric name as candidates with when each was written, never as a deterministic fact.
- **`rb tour` runs on a clean install** and in the loop's order: the criteria are declared and frozen before the runs write their outputs.
- **Fail closed, in more places.** A record file only a newer rb reads is named and never read, written over or restored, and this rb writes nothing while one exists; so is a declared relation of a kind or orientation only a newer rb knows, while the rest of its record still reads, and `rb clone` refuses a bundle that holds either rather than leave it behind; an unreadable criteria file stops its criteria with `E_STATE_CORRUPT` instead of hiding them; a second copy of a record in another file is caught as written outside rb, set aside by `rb doctor --restore`, and never adoptable; retracting an experiment keeps its criteria in every gate, and `rb status` gives each of them the one repair it takes (`experiment_retracted`: `rb retract <criterion>`), never a command that writes to the retracted experiment.
- **A hand edit is named as one.** Format 1 is fixed: a later rb that adds a field writes a new format, which an older rb reads as needing an upgrade. A field or value rb does not know, in a file that is not what rb last wrote, is said as edited by hand or written by a newer rb (still `E_STATE_NEWER`), naming the file, a part's own where an experiment is read with it, and the fix offers `rb doctor --restore` beside the upgrade where rb holds its last write; `rb doctor` says the same, once, `rb open` draws the fix under the message (`fix` beside `error`), and `rb ui` gives the terminal back and says both.
- **A misspelled metric is named, not refused.** `rb criterion add` with a `--metric` that no run or analysis reports and the catalogue does not hold, close to a name one of them does (`change.val_los` beside `val_loss`), says so in one warning line naming that name (`data.warnings`, and an RBWarning from the SDK's `criterion()`); the criterion is declared as given, since its metric declares the name by use. Declared before any run, a run under the close name says the criterion likely misspells it, and `rb status` gives it the retraction as its step, never the misspelt name.
- **A run that counts toward nothing says so.** `rb run add` whose numbers no criterion of the experiment reads (a flat `{"val_loss": ...}` where the criteria read `fp32.val_loss` and `int8.val_loss`) records the run and says in one line that it counts toward nothing, with the names its criteria read and the shape a file gives them in, `{"fp32": {"val_loss": ...}, "int8": {"val_loss": ...}}`, or `--variant <name>` for one variant's numbers; the SDK's `run.log` says the same as an RBWarning. The README shows that shape.
- **After `uvx`, the way to keep going.** `rb tour` run by `uvx --from rabbit-brain` ends with how to run its next commands while `rb` is not on the path (`uvx --from rabbit-brain rb ui`, or `uv tool install rabbit-brain`), and the README says so after the `uvx` route.
- **Third-party notices ship with rb.** Each wheel, the sdist and the GitHub release carry `THIRD-PARTY-NOTICES`, the licenses of the crates built into the `rb` binary.
